# Architecture Consolidation Plan

Status: planning only. No work starts before the 2026 boards (exam Sep 28, 2026). This
document is the reference for the post-boards revamp.

## The question

The app runs on two stacks:

- **React / Next.js** for the main app (levels, practice, exam, notes, drill, review,
  readiness, admin, account, search). Content lives as data in `src/data/*`, behavior
  lives in shared components and server routes, auth and access run through middleware.
- **Static HTML** for the whole Top 2 area (reviewers, subject exams, preboard sets,
  cards, the mock board, the CBLE simulator, the home dashboard). 162 `.html` files
  under `public/top2/`, generated by 18 Python scripts in `exam-build/`.

Which is easier to maintain, and what should we standardize on?

## Short answer

Standardize on the **React / Next.js app**, and move Top 2 content into the same
data-driven model. React is the more maintainable system here for one reason: behavior
lives in one place and applies everywhere at once. Static HTML spreads the same behavior
across 162 files, so every change is 162 chances to miss one.

We are already paying for the split. Recent examples, all caused by the same fix landing
in one stack but not the other:

- The fan-dial cylinder MCQ existed as data in `src/data/primary-eye-care.json` (wrong
  key) and again inside a static preboard page (correct key). Same question, two copies,
  two different answers.
- The "added to your review queue" prompt was gated by `reviewAccess` in the React
  results and drill screens, but the React practice screen was missed, so a basic user
  saw it.
- Usage tracking ran only in the React app, so users disappeared from the Usage tab the
  moment they opened a static Top 2 page. We just patched this by hand-injecting a script
  into all 162 files. That patch is exactly the kind of per-file work the single-system
  model removes.

Question content is currently duplicated across at least four places: the static reviewer
pools, the extracted `cble-bank.js`, the preboard HTML files, and `src/data/*`. That is
the root maintenance cost. One question, one home, is the biggest single win available.

## Where each stack is strong

- **Static HTML** is cheap to mass-produce from Python, renders instantly, and has no
  build step for a content author. It was the right call for shipping a large reviewer
  fast during prep.
- **React / Next.js** gives one design system, one quiz engine, one access layer, one
  analytics layer, and data-driven content. A fix or a new feature (SRS, option shuffle,
  tracking, gating) is written once and every screen inherits it.

For maintainability, consistent design, and a coherent user-flow, React wins clearly.
The only real cost of consolidating is the migration itself.

## Target architecture

- **One app: Next.js.** Every Top 2 surface becomes a React route (for example
  `/top2/exam/[subject]`, `/top2/reviewer/[subject]`), sharing the main app's shell,
  auth, access control, and `<UsageTracker/>`.
- **One question store.** All items live in a single typed data source (the `src/data`
  model, extended with a Top 2 flag or namespace). No embedded copies in HTML, no
  `cble-bank.js` fork. The CBLE simulator reads the same store.
- **One quiz engine.** A single component powers main-app exams, Top 2 exams, preboards,
  and the CBLE simulator. Option shuffling, SRS recording, review gating, scoring, and
  results all live in it once.
- **One reviewer renderer.** Long-form reviewers become content (MDX or structured JSON
  sections) rendered by a shared component that already carries reading-position and
  cover-and-recall. Authoring stays simple; behavior stays shared.
- **Python becomes data-prep only.** The scripts keep cleaning and importing source
  material, but they output data into the single store. They stop emitting HTML pages.

## Migration phases (incremental, low risk)

Each phase ships on its own and leaves the app working. Old URLs are preserved with
redirects so existing bookmarks and links keep working.

1. **Freeze and inventory.** Stop adding new static pages. New Top 2 content goes into the
   data store from now on. Write down every static URL so we can redirect it later.
2. **Unify the question store.** Make `src/data` the single source of truth. Import the
   static pools and retire `cble-bank.js` as a separate copy. De-duplicate against the
   main-app items.
3. **Unify the quiz engine.** Point the CBLE simulator and a first Top 2 subject exam at
   the shared engine and store as React routes. Confirm parity (scoring, SRS, tracking,
   access) against the static version, then redirect the old URL.
4. **Migrate the reviewers.** Move long-form reviewers to the content renderer, subject by
   subject, preserving reading-position and recall.
5. **Migrate the master-index tools.** Port the home dashboard, simulator, cheat sheet,
   and trackers to React routes.
6. **Retire the static stack.** Once every surface is migrated and redirected, delete
   `public/top2/*.html` and the HTML-emitting generators. Keep the data-prep scripts.

## Interim rules (until the revamp)

To stop further drift while the app stays as-is for boards:

- One source of truth for any given question. If an item exists in `src/data`, do not also
  embed it in a static page, and vice versa. Fix it once.
- New Top 2 content is authored in the data store, not as new HTML.
- Any shared behavior (tracking, access gating, SRS) added to the React app must be
  checked against the static pages the same day, or explicitly logged here as a known gap.

## Timing and effort

- **When:** after the 2026 boards, folded into the post-boards roadmap. Not during prep.
- **Effort (rough):** the quiz-engine and question-store unification is the large piece;
  the reviewer migration is medium and can go subject by subject; the tooling and cleanup
  are small. It is a series of small, shippable steps, not a single rewrite.

## Open decisions (to settle before phase 1)

- Reviewer authoring format: MDX vs structured JSON sections.
- URL scheme for migrated Top 2 routes, and the redirect map from the old `.html` paths.
- Whether Top 2 and main-app content share one namespace or stay separated by a flag.
